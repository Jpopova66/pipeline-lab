# Задание 3. Осознанный .trivyignore

**Что делаем:** разбираемся, что делать с находками сканера, на
которые нельзя (или не нужно) реагировать прямо сейчас.

## Ситуация

Даже на свежем базовом образе Trivy что-то находит — например,
уязвимости без доступного исправления. Ронять на них пайплайн
месяцами нельзя, но и забыть про них — тоже.

## Что сделать

1. Посмотрите полный отчёт Trivy в последнем прогоне (или прогоните
   локально: `trivy image <образ>`). Выберите **одну конкретную**
   находку: запишите её CVE, пакет и severity.
2. Возьмите `templates/.trivyignore`, положите рядом с workflow
   (в корень репозитория) и впишите туда этот CVE **с комментарием**:
   почему подавляем и когда пересмотрим.
3. Подключите файл в шаге Trivy (параметр `trivyignores` у action —
   проверьте имя параметра в документации aquasecurity/trivy-action).
4. Дополнительно разберитесь с параметром `ignore-unfixed` — и
   письменно ответьте: стоит ли включать его в нашем пайплайне
   и почему.

## Критерий приёмки

Прогон зелёный, в логе Trivy подавленная находка не показывается,
в `.trivyignore` есть CVE и осмысленный комментарий. Подавлять
CRITICAL без внятного обоснования — нельзя, защитите своё решение
словами.

## В отчёт

- содержимое `.trivyignore`;
- ответ про `ignore-unfixed` (2–3 предложения).
